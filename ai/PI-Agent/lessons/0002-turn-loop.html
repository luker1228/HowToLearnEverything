Lesson 2 · pi-agent-core

一轮 Turn 是怎么跑起来的

目标：打开 agent-loop.ts，看清一次 prompt() 内部到底跑了几轮、什么时候继续、什么时候停。

热身回忆：上一课说，Agent 类的实例持有状态，真正不持有状态、纯函数式的那个文件叫什么？

1. 书里给的循环骨架

《深入理解 AI Agent》第一章给出过一段刻意简化的伪代码，描述任何 Agent 循环的最小骨架：

observation = Environment.observe()
trajectory = [observation]
while true:
    actions = Model(Harness.build_context(trajectory))
    if len(actions) == 0:
        break
    allowed_actions = Harness.constrain(actions)
    observation = Environment.apply(allowed_actions)
    if not Harness.verify(Environment):
        observation = Harness.correct(Environment)
    trajectory.append(allowed_actions, observation)

五个动作构成一个闭环：上下文与工具让 Agent 能做事；约束、验证、纠正让 Agent 不做错事。这一课我们只对照前两步——「模型采样下一步」和「没有更多动作就退出」——剩下的约束/验证/纠正留给下一课，因为那部分内容足够多，值得单独一课。

2. 对照真实代码：runLoop 的内层循环

agent-loop.ts 里真正驱动一轮又一轮的，是 runLoop() 函数里的一个内层 while 循环，条件是一个叫 hasMoreToolCalls 的布尔变量：

let hasMoreToolCalls = true;
while (hasMoreToolCalls || pendingMessages.length > 0) {
    // ① 调 LLM，拿到 assistant 的这轮回复
    const message = await streamAssistantResponse(...);

    // ② 看这条回复里有没有工具调用
    const toolCalls = message.content.filter(c => c.type === "toolCall");

    hasMoreToolCalls = false;
    if (toolCalls.length > 0) {
        // 执行工具（下一课细讲）
        hasMoreToolCalls = !executedToolBatch.terminate;
    }

    await emit({ type: "turn_end", message, toolResults });
    if (await config.shouldStopAfterTurn?.(...)) {
        await emit({ type: "agent_end", messages: newMessages });
        return; // 强制停下
    }
}
骨架里的步骤真实代码
actions = Model(...)streamAssistantResponse()（调 LLM，见 agent-loop.ts:281-372）
if len(actions) == 0: break本轮 message.content 里没有 toolCall → hasMoreToolCalls 保持 false → 循环条件不满足，自然退出

关键洞察：「继续跑下一轮」这件事，完全是由「assistant 这轮要不要调工具」决定的。模型自己选择不调任何工具（比如它认为任务做完了，直接回复文字），循环就自然停下——这是最常见的「自然结束」路径。

小测验 1：决定「这轮结束后还要不要再跑一轮」的那个布尔变量叫什么？

3. 除了「自然停下」，还有「被叫停」

光靠模型自己决定不够——生产系统往往需要额外的强制刹车，比如「已经跑了 50 轮还没完成，强制停下防止跑飞」。这就是 shouldStopAfterTurn 钩子：每轮 turn_end 之后都会问一遍「要不要现在就停」，只要它返回 true，循环立刻 return，发出 agent_end。

所以一次 prompt() 有且只有两条退出路径：

  1. 自然停下：assistant 某一轮的回复不含工具调用（len(actions)==0 的真实版本）
  2. 被叫停：shouldStopAfterTurn 返回 true（应用层强加的终止条件，比如轮数上限、预算上限）

一个容易搞混的地方：书里第一章还提到一个更高层的概念叫「Loop 工程」——「把视野从单次运行扩展到跨轮次的持续自主运转：谁来发现下一件该做的事、何时验证、何时才算真正完成」。这节课讲的 turn 循环不是 Loop 工程，它只是一次 prompt() 调用内部的反馈循环，属于书里定义的「Harness 工程」范畴——「涵盖上下文与工具接口、约束机制、验证手段、反馈循环和错误恢复等 Agent 边界内、模型之外的运行与治理机制」。Loop 工程关心的是跨越多次任务、甚至跨会话的自主运转（比如一个常驻后台、自己找活干的 Agent），层级比这节课讲的东西高一层。

这一课讲的「没工具调用就停,否则继续下一轮」的 turn 循环,按书里的五阶段范式,属于哪一层?
