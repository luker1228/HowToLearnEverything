大图：Agent = LLM + 上下文 + 工具

目标：读完这节课，你能一眼指出 pi-agent-core 源码里哪一段代码对应「大脑 / 眼睛 / 手脚」，并说清 Agent 类和 agent-loop.ts 谁负责什么。

本课主参照：李博杰《深入理解 AI Agent》第一章「AI Agent 入门」。在线阅读，本地也有源码：ai-agent-book/book/chapter1.md。建议正式学习前先通读一遍第一章开头的「现代 Agent = LLM + 上下文 + 工具」这一节，本课只摘取和代码直接对应的部分。

1. 一个公式，三个部件

现代 Agent 的最小工程实现可以写成一个公式：

Agent = LLM（大脑） + 上下文（眼睛） + 工具（手脚）

这里的「+」是工程组件的组合，不是数学加法。三个词都要按广义理解：

直觉是什么不是什么
大脑（LLM）Agent 的决策内核：理解意图、规划、判断不只是模型权重本身
眼睛（上下文）每个决策点 Agent 手上握有的全部信息：历史消息、用户记忆、任务进展不只是「喂给模型的一段 prompt 文本」
手脚（工具）Agent 感知/改变外部世界的接口——定义、调用协议、适配器不只是「函数调用」这一种形式

书里还给出了一个更关键的分层：Model–Harness 结构。Model 只负责策略决策（也就是纯粹的 LLM 推理）；Harness 是环绕在 Model 外面的运行与治理层——它构造上下文、暴露工具接口、维护循环状态、做权限校验和纠错。用公式表达：LLM = Model，上下文 + 工具 = 最小 Harness。

这不是巧合——pi-agent-core 源码里真的有一个叫 harness/ 的目录（pi/packages/agent/src/harness/），下面还分了 tools/、compaction/、session/、env/ 四个子模块。这套代码库的作者显然也是照着这个 Model–Harness 心智模型设计的。

2. 把公式对应到源码

公式部件pi-agent-core 里对应什么在哪个文件
大脑（LLM）不在这个包里！由 streamFn 参数注入（来自 @earendil-works/pi-ai），Agent 只负责调用它src/agent.ts（streamFunction 字段）
眼睛（上下文）systemPrompt + messages，外加一条处理管线把「App 消息」转成「LLM 消息」src/types.ts（AgentMessage）、src/agent.ts（state.messages）
手脚（工具）AgentTool[]，工具的定义、执行前后钩子（beforeToolCall/afterToolCall）src/types.ts（AgentTool）、src/harness/tools/
Harness（运行与治理层）驱动整个循环、管理会话状态、压缩历史消息src/agent-loop.ts + src/harness/*

注意大脑这一格：pi-agent-core 本身不包含任何模型推理代码。它通过构造函数注入的 streamFn 与真正的 LLM 解耦——这是一种依赖注入。这也是为什么这个包的 package.json 描述自己是「transport abstraction, state management」而不是「LLM wrapper」。

3. Agent 类到底是什么角色？

Agent（src/agent.ts）不是循环本身，它是循环外面的一层「有状态外壳」：

  • 持有当前状态：messages、tools、model、isStreaming、streamingMessage、pendingToolCalls……
  • 把真正的推理-工具循环委托给 runAgentLoop()（定义在 agent-loop.ts，是一个不持有状态的纯函数）
  • 用一个 processEvents(event) 方法，把循环发出的每个事件归约（reduce）成新的状态——每处理完一个事件，就把结果写回 this._state 上对应的字段
  • 再把事件转发给所有 subscribe() 的监听者，供 UI 更新

换句话说：agent-loop.ts 导出的 runAgentLoop 是一个不持有状态的纯函数，每次调用都要把当前状态完整传进去（createContextSnapshot()）；Agent 类的实例才持有真正的状态，负责保存状态、暴露给外部读写。

4. 调用 prompt() 时，事件是怎么流动的？

这是 官方 README 里给出的事件时序（无工具调用的最简单情况）：

prompt("Hello")
├─ agent_start
├─ turn_start
├─ message_start   { message: userMessage }
├─ message_end     { message: userMessage }
├─ message_start   { message: assistantMessage }
├─ message_update  { message: partial... }   // 流式增量
├─ message_update  { message: partial... }
├─ message_end     { message: assistantMessage }
├─ turn_end        { message, toolResults: [] }
└─ agent_end        { messages: [...] }

如果 assistant 的回复里带了工具调用，流程会在 message_end 之后岔出一段工具执行事件，执行完再回到 turn_end。完整的事件类型定义在 src/types.ts 的 AgentEvent（一个联合类型，一共 9 种事件）。
