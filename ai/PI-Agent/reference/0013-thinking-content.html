思考内容：跟文本、工具调用平级的第三种内容块

配套 Lesson 13。核心结论：pi 没有为"思考"发明任何专门机制，它是既有两套系统（内容类型、流式事件）里各多出的一个平级分支。

类型层：ThinkingContent

// pi-ai/src/types.ts:429
AssistantMessage.content: (TextContent | ThinkingContent | ToolCall)[]

// types.ts:356-364
interface ThinkingContent {
  type: "thinking";
  thinking: string;
  thinkingSignature?: string;  // provider 不透明回放数据，多轮续接用
  redacted?: boolean;          // 为真时文字被安全过滤器隐去，加密凭证仍在 thinkingSignature
}

流式事件层：三组事件严格对称

事件三元组负责的内容块
text_start / text_delta / text_endTextContent
thinking_start / thinking_delta / thinking_endThinkingContent
toolcall_start / toolcall_delta / toolcall_endToolCall

agent-loop.ts:326-344 用同一个 case 分支处理这九种事件——收到任意一种，只做「partialMessage = event.partial，转发成 message_update」，不区分种类。拼接碎片、认领 contentIndex 的工作在 provider 端完成，agent-loop.ts 不参与。

开关链路：谁决定这一轮要不要输出思考

Agent._state.thinkingLevel        // "off"|"minimal"|"low"|"medium"|"high"|"xhigh"|"max"，默认 "off"
  → config.reasoning              // agent.ts:450，"off" → undefined
    → streamFunction(model, ctx, { ...config, apiKey, signal })   // agent-loop.ts:308，整个 config 展开进 provider 调用

reasoning 落地成具体 provider 参数（如 token 预算）是 pi-ai 内部的事，按 Mission 范围不展开。ThinkingBudgets（等级→token 预算的映射）同样来自 pi-ai，agent 包只是原样传递等级。

为什么需要 thinkingSignature/redacted

某些 provider 的多轮推理要求原样回放上一轮的思考块，否则推理链条失效——thinkingSignature 就是为此保留的不透明凭证。redacted 处理"文字被隐去但凭证仍需保留"的情况。含义：AgentMessage 轨迹（参考卡片 4）里带 ThinkingContent 的消息不能被随意摘要/改写，否则可能丢掉这个凭证——具体压缩逻辑（参考卡片 5）对此的处理方式，留作后续追问点，本卡暂未验证。
