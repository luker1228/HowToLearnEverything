关键文件一览

文件角色
src/agent.ts有状态外壳：持有 state、订阅者列表、steering/follow-up 队列；把事件 reduce 成新状态

src/harness/env/环境相关封装

消息处理管线

AgentMessage[] → transformContext() → AgentMessage[] → convertToLlm() → Message[] → LLM
  • transformContext（可选）：裁剪旧消息、注入外部上下文
  • convertToLlm（必需，有默认实现）：过滤掉纯 UI 消息，把自定义消息类型转成 LLM 认识的 user / assistant / toolResult

为什么要区分：LLM 只认识 user/assistant/toolResult 三种角色，但应用层往往需要更丰富的消息类型（比如纯 UI 提示、系统事件），AgentMessage 通过声明合并（declaration merging）支持这些自定义类型。

AgentEvent 全部 9 种（src/types.ts）

事件何时触发
agent_start一次 prompt()/continue() 调用开始
turn_start一轮 turn（一次 LLM 调用 + 可能的工具执行）开始
message_start某条消息开始（用户消息或 assistant 消息）
message_updateassistant 消息流式增量到达
message_end某条消息完成，被 push 进 state.messages
tool_execution_start某个工具调用开始执行
tool_execution_update工具执行过程中的流式中间结果
tool_execution_end工具执行结束（成功或出错）
turn_end一轮 turn 结束，带上这轮的 assistant 消息和所有工具结果
agent_end整次 prompt()/continue() 调用结束，带上本次新增的全部消息

Agent 的 state 字段

字段含义
systemPrompt系统提示词
model当前使用的模型描述对象
tools当前可用的工具列表
messages完整的历史消息（上下文核心）
isStreaming是否正在等待/接收 LLM 输出
streamingMessage正在流式生成、尚未 message_end 的那条消息
pendingToolCalls正在执行、尚未返回结果的工具调用 id 集合
errorMessage本轮如果出错，错误信息
