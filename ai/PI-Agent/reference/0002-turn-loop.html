turn_end vs agent_end

turn_end = 「一次 LLM 调用 + 它触发的整批工具调用（0~N 个，一起算一轮）跑完了」，不是「一次工具调用跑完了」——如果这轮 assistant 消息里有 3 个 toolCall，无论顺序还是并行执行，3 个全部结束才发一次 turn_end。

turn_start
 └─ streamAssistantResponse()   1 次 LLM 调用 → 1 条 assistant 消息
 └─ executeToolCalls()          这条消息里的全部 toolCall，当一批一起跑完
turn_end                        整批都结束后才发一次

agent_end 每次 prompt()/continue() 调用只发一次，turn_end 可以发很多次（模型每多来一轮 LLM 调用就多一个 turn_end）。只有触发停止条件（自然停 / shouldStopAfterTurn）的那一次 turn_end，后面才会紧跟着发 agent_end。关系可以写成：

agent_start
  turn_start → ... → turn_end   ─┐
  turn_start → ... → turn_end    │ 重复 N 次（N = 这次 prompt() 里 LLM 被调用的次数）
  ...                            │
  turn_start → ... → turn_end   ─┘ ← 最后一次，紧跟着触发停止
agent_end

Harness 工程 vs. Loop 工程（别混淆）

范围本课对应哪个
Harness 工程单次 prompt() 调用内：上下文/工具接口、约束、验证、反馈循环、错误恢复✓ 这一课讲的 turn 循环就在这一层
Loop 工程跨多次任务、甚至跨会话：谁来找下一件要做的事、何时算真正完成✗ 更高一层，暂不涉及
