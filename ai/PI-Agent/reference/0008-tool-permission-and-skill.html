工具执行的权限控制，以及 Skill 和 Tool 的区别

配套 Lesson 8。可打印，随时回来查。

权限控制：两层拦截

层位置机制
① 没注册的工具agent-loop.ts:607-614currentContext.tools?.find(...) 找不到就直接返回 Tool xxx not found 错误，根本进不到执行阶段
② 已注册工具的执行前检查agent-loop.ts:619-646config.beforeToolCall(context, signal) 返回 { block: true, reason } 就不执行，改成一条错误 tool 结果返回给模型

BeforeToolCallResult（types.ts:61-69）：block/reason/terminate。关键事实：内置工具 bash/edit/read/write（harness/tools/*.ts）自己都没有权限检查代码——beforeToolCall 是纯扩展点，问不问、怎么问，全由把这些工具组装进 Agent 的 App 决定。跟 Lesson 1 的 streamFn、Lesson 4 的 convertToLlm 同一个套路：harness 只留钩子，不做决策。

Skill 接口：没有 execute，没有参数 schema

export interface Skill {                       // harness/types.ts:46-57
	name: string;
	description: string;
	content: string;        // 完整技能说明文本
	filePath: string;
	disableModelInvocation?: boolean;
}

对比 AgentTool（types.ts:386-409）：有 execute()、parameters（JSON Schema）、executionMode。Skill 一个都没有——它是一段内容，不是一个可调用的动作。

模型怎么"看见" Skill：只有名字和描述，不含全文

<available_skills>                          // formatSkillsForSystemPrompt, system-prompt.ts:3-23
  <skill>
    <name>xxx</name>
    <description>xxx</description>
    <location>/path/to/SKILL.md</location>
  </skill>
</available_skills>

只塞 name/description/filePath 进系统提示词，content（全文）不在里面。

真正"用"一个 Skill：拼字符串塞进上下文，不走工具调用链路

export function formatSkillInvocation(skill: Skill, additionalInstructions?: string): string {
	// skills.ts:38-41 —— 只是拼一段 <skill>...</skill> 字符串，把 skill.content 全文包进去
}

不产生 tool_execution_start/_end 事件，不经过 beforeToolCall/afterToolCall——它不在 Lesson 6 讲过的「assistant 发 toolCall → prepareToolCall → execute() → tool_execution_*」这条链路上。什么时候注入哪个 Skill 全文，由调用这个函数的上层（App/更高层 harness）决定。
