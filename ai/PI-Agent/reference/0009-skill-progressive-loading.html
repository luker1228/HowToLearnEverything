Skill 怎么被渐进式加载，谁来决定用哪些

配套 Lesson 9。可打印，随时回来查。范围注意：本课主要引用 packages/coding-agent，不是之前几课的 packages/agent——因为 packages/agent 里对应的整合逻辑（AgentHarness.skill()）是空实现（agent-harness.ts:368-370）。

三个阶段（Agent Skills 规范「Progressive disclosure」原文定义）

阶段内容触发/重建时机
1 · Metadata（~100 tokens）name/description/location（<available_skills>），过滤掉 disableModelInvocation=true 的会话开始、工具集变化（agent-session.ts:944-953）、扩展资源变化（:2407-2409）时重建，缓存进 _baseSystemPrompt，不逐轮重算；进的是 systemPrompt，不是 messages
2 · Instructions（<5000 tokens 建议）完整 SKILL.md 正文，包进 <skill name=... location=...>...</skill>见下方两条路径；进的是 messages，不是 systemPrompt
3 · Resources（按需）scripts//references//assets/ 里的具体文件模型判断 Instructions 正文里提到的某份资料/脚本真正用得上时，再发起一次普通 read/bash；可能永远不发生
扫描磁盘 → 提取 name+description(+location)
        → 拼进 systemPrompt          ═══ Stage 1 Metadata
        → 每次模型调用原样带上
        → 模型判断 description 相关？
            ├─ 否 → 结束
            └─ 是 → 路径 B（模型 read）或路径 A（用户 /skill:name）
                 → SKILL.md 全文进 messages   ═══ Stage 2 Instructions
                     → 正文引用 scripts/references/assets？
                         → 模型按需再 read/bash  ═══ Stage 3 Resources

Stage 1 → Stage 2 的两条路径：模型自主发现为主，人工强制为兜底

coding-agent/docs/skills.md「How Skills Work」原文：「When a task matches, the agent uses read to load the full SKILL.md (models don't always do this; use prompting or /skill:name to force it）」——这句话定了主次关系，不是猜的。

决策者时机机制定位
路径 B：模型主动读模型模型调用过程中系统提示词原文（skills.ts:364）："Use the read tool to load a skill's file..."——模型发起一次普通 read 工具调用，照常经过 Lesson 8 的 beforeToolCall/事件链路，无特殊待遇规范描述的默认设计
路径 A：/skill:name用户（打字时就已决定）模型调用开始之前_expandSkillCommand（agent-session.ts:1320-1341）同步 readFileSync，拼进消息文本；调用点在 :1169-1174，发给 agent 之前模型没自主发现时的可靠性兜底

关键点：路径 A 不查 disableModelInvocation——这个标记只影响 Stage 1 列表里"看不看得见"，不影响"能不能被显式点名调用"。

另一种设计：专门的 load_skill(name) 工具（对照，不是 pi 的做法）

Learn Claude Code 教程和这次对话里实际可调用的 Skill 工具，用的是同一个模式：按名字查注册表，不接受任意文件路径。

pi：通用 read + 路径load_skill(name) + 注册表
安全边界路径就是路径，全靠 beforeToolCall 自己判断不接受任意路径，天然没有路径遍历风险
权限钩子看到的信息看到的是"要读某个路径"，跟读别的文件长得一样能看到"这是一次 skill 调用"这个明确语义

两种都真实存在，规范只规定效果（渐进式加载），不规定具体触发机制。

"用哪些 Skill"没有智能筛选，靠的是 description 写得够不够具体

Stage 1 列表永远是全部（未禁用的）已发现 Skill，不按当前 prompt 做相关性排序/检索。路径 B 里模型要不要读某个 Skill，完全靠它自己读 description 文本判断——这也是规范强调"description 要写具体"的原因（Helps with PDFs. 被明确标成 Poor 示例）。

发现来源：不只是两个目录

层级来源
全局~/.pi/agent/skills/、~/.agents/skills/
