Session：多次 run 怎么串成一棵树

配套 Lesson 10。可打印，随时回来查。范围注意：本课讲的是 packages/coding-agent 真正在用的一套（SessionEntry/SessionManager），不是 packages/agent/src/harness/session 里那套定义齐全但未被接上的 Record/runId 系统。

存储的基本单位：只认父节点，不认"第几次 run"

export interface SessionEntryBase {   // session-manager.ts:46-51
	type: string;
	id: string;
	parentId: string | null;   // 只指向"我的上一条"
	timestamp: string;
}

没有 runId 字段。"这些消息属于同一次 run"是从"下一条顶层 role==="user" 的消息开始新 run"这个模式推出来的，不是持久化字段本身。

树的形成：父指针分组

export interface SessionTreeNode {    // session-manager.ts:159-165
	entry: SessionEntry;
	children: SessionTreeNode[];        // 同 parentId 的多条 entry = 多个分支
}

跟 git commit 图同构：正常情况下每个节点一个孩子，退化成一条线；有分叉才用得上"树"。

分叉怎么触发：fork()，两种 position

position场景行为
"at"/clone 复制当前会话targetLeafId = selectedEntry.id，原地分叉
"before"（默认）选中一条用户消息回退重说targetLeafId = selectedEntry.parentId，取出消息原文塞回输入框

关键点：分叉不是在同一文件里加节点，是 sessionManager.createBranchedSession(targetLeafId) 真正开一个新会话文件，新文件记着父会话是谁（agent-session-runtime.ts:262-338）。磁盘上的"树"其实是一组互相记父会话的独立文件家族。

未被采用的另一套设计（对照，别搞混）

packages/agent/src/harness/session/types.ts 定义了 OperationStartedRecord/OperationFinishedRecord（带 runId，intent.kind: "run"|"compaction"|"navigation"）和 SessionTree/ForkOptions{scope:"branch"|"tree"}——类型齐全、有单测（reducer.test.ts），但 coding-agent/src/ 里搜不到任何调用。跟 Lesson 9 的 AgentHarness.skill() 是同一种"设计已经写好、产品没接上"的情况。
