Steering：Agent 正在工作时怎么插入新指令

配套 Lesson 7。可打印，随时回来查。

为什么需要它（先看这个）

prompt() 在 activeRun 存在时直接抛错（agent.ts:351-354）：「Agent is already processing a prompt. Use steer() or followUp() to queue messages, or wait for completion.」——同一时间只能有一次 runAgentLoop 在跑，不能靠再调一次 prompt() 追加指令。steer()/followUp() 就是错误信息里指名的正确 API。

steer() 只做排队，不直接接触运行中的循环

steer(message: AgentMessage): void {          // agent.ts:283-285
	this.steeringQueue.enqueue(message);
}

同步方法，立刻返回。真正的"什么时候被送进对话"由 runAgentLoop 那一侧决定。

注入时机：轮次边界，不是"立刻打断"

检查点位置作用
循环刚进入时agent-loop.ts:166应对"用户在等待期间已经打字"的情况
每一轮 turn_end 之后，下一轮开始前agent-loop.ts:259：pendingMessages = (await config.getSteeringMessages?.()) || []常规的"跑起来之后再插入"

types.ts:236 文档原文：「Called after the current assistant turn finishes executing its tool calls, unless shouldStopAfterTurn exits first.」——当前这一轮发起的工具调用（哪怕是并行的好几个）必须全部跑完，steer() 排的消息才会被 drain 出来，不会打断正在执行中的工具调用。

队列的排空策略：PendingMessageQueue.drain()

drain(): AgentMessage[] {                     // agent.ts:141-154
	if (this.mode === "all") {
		const drained = this.messages.slice();
		this.messages = [];
		return drained;
	}
	const first = this.messages[0];
	if (!first) return [];
	this.messages = this.messages.slice(1);
	return [first];                             // 默认只取最早一条
}

默认 mode 是 "one-at-a-time"（agent.ts:231）：连续 steer() 三次，会分散在接下来三轮里逐条注入，不是一次性全塞进去。想一次性全部注入要显式设 steeringMode = "all"（setter 在 agent.ts:264-266）。

steer() vs followUp()

什么时候被 drain效果
steer()当前轮工具调用跑完后，下一轮开始前（agent-loop.ts:259）插进正在进行的运行，提前影响走向
followUp()Agent 已经没有更多工具调用、steering 队列也空、本来要停下的那一刻让 Agent 多跑一轮，而不是打断

followUp() 定义（agent.ts:288-290）跟 steer() 写法一样，只是排进另一个独立队列 followUpQueue；types.ts:249-256 是它的消费时机文档。
